# NOTAM classification: taxonomy, data, training and evaluation

*Research decision-support prototype; not certified and not for operational use.*

Every number in this document comes from `evaluation/results/classifier_eval.md`, generated by `python -m classification.evaluate` on 21 Nov 2026 from the final annotated sheet. Re-run that command after any change to the data and update the tables.

## 1. Status of the human annotations

`data/labelled/aai_label_sheet.csv` is the final annotated sheet supplied by the project team (21 Nov 2026): 300 AAI NOTAMs, 300 distinct NOTAM identities, every row with a valid `human_category` and `human_severity`. Labels were loaded as supplied; no label was changed by the code.

AIRSPACE and OTHER have no annotated examples, so they cannot be evaluated on AAI data. The labels are `human_preliminary`: one annotator, no agreement study (see section 9).

## 2. Taxonomy (`classification/taxonomy.py`)

One module defines the labels. The following all import from it:

- Q-code rules, the ML model, training and evaluation;
- the annotation validator;
- the API schema.

A test checks that the database CHECK constraints in `002_notam_pipeline.sql` list exactly the same values.

| Category | NOTAM-code subjects (ICAO Doc 8126) | Examples |
|---|---|---|
| AIRSPACE_RESTRICTION | R* | restricted / danger / prohibited area, TRA |
| NAV_WARNING | W* | rocket launch, firing, UAS, parachuting, exercises |
| AERODROME | F*, L*, MX/MP/MA/MN | aerodrome hours/closure, taxiway, apron, lighting |
| RUNWAY | MR/MT/MD/MS/MW/MU/MK | runway closure, declared distances |
| NAVAID_COMMS | N*, I*, G*, C* | VOR/DME/ILS/GNSS outage, radar, comms |
| OBSTACLE | O* | cranes, towers, obstacle lights |
| PROCEDURE | P*, A*, S* | approach/SID/STAR changes, ATS routes, ATS units |
| OTHER | K*, X*, unknown | checklist, plain language |

**Mapping strategy.**

- **No category is merged.** The AAI sample naturally contains only six of the eight. That is expected: the AAI summaries are mostly aerodrome NOTAMs. AIRSPACE_RESTRICTION and OTHER stay in the taxonomy, and evaluation lists them as "classes absent from the reference" rather than silently dropping them.
- **Label normalisation.** Annotation labels are trimmed, upper-cased and have spaces and hyphens replaced by underscores. A short, explicit alias table maps a few synonyms (e.g. `NAVAID` → `NAVAID_COMMS`). Every alias use is reported by the validator, and anything else is rejected as invalid.

**Severity semantics (unchanged from `classification/rules.py`).**

| Severity | Meaning |
|---|---|
| BLOCKING | The airspace or aerodrome is unusable while the NOTAM is active. |
| RESTRICTIVE | Usable with limitations. |
| ADVISORY | Information only. |

BLOCKING is a property of the NOTAM, not of a route. A route is rejected only when it overlaps the NOTAM in space, flight level and time (see `docs/routing_methodology.md`).

## 3. Data sources for training

| Source | Label type | Count (21 Nov run) |
|---|---|---|
| autorouter records with an unambiguous Q-code | `weak_qcode` (rules applied to the Q-code) | 108 after de-duplication |
| ISRO launch NOTAM fixtures (ICAO text) | `weak_qcode` | 3 |
| AAI texts whose NOTAM identity matches an autorouter record | `weak_qcode` | 3 after de-duplication (15 before) |
| AAI annotation sheet | `human_preliminary` | 300 valid; 199 development NOTAMs used for training, 101 frozen hold-out never trained on |

Every example carries `source`, `label_type` and its NOTAM identity (`nof|notam_id`).

**De-duplication** (`dataset.combine_examples`):

- **Exact text duplicates.** Texts that are identical after normalisation are kept once. 16 of the 130 weak examples were such duplicates, mostly the same NOTAM seen through AAI and autorouter, leaving 114.
- **Same NOTAM in weak and human data.** The human label is kept, and any disagreement with the weak label is listed in the merge report.
- **Same text, different labels.** If the conflict is between different NOTAMs, it is recorded rather than hidden. If it is within one NOTAM's annotations, that field is excluded until it is resolved.

## 4. Annotation validation and audit (`classification/annotations.py`)

Run `python -m classification.annotations`. It writes `evaluation/results/annotation_audit.md` and `.json`. Labels are never changed automatically.

| Level | Check |
|---|---|
| error | missing / invalid label; malformed NOTAM identity; empty E-text; same NOTAM labelled differently in two rows |
| warning | alias or case normalisation applied; duplicate identity with identical labels |
| review | identical text labelled differently across NOTAMs; severity contradicting `rules.py` definitions; generic note on a row whose label differs from the prediction; prediction ≠ annotation (listed, not judged) |

The **severity-semantics review** compares each label with the rule definitions and explains any departure. Examples:

- a runway closure labelled BLOCKING (rules: RESTRICTIVE unless the aerodrome itself is closed);
- an aerodrome closure labelled ADVISORY (rules: BLOCKING);
- UAS or parachuting labelled BLOCKING (rules: RESTRICTIVE);
- "deactivated" or "cancelled" activity labelled BLOCKING.

Every BLOCKING annotation gets its own section listing:

- the text cues found;
- the specific review reasons;
- otherwise the explicit statement that it is still unverified.

The cues are used only to raise flags; they are not used for prediction.

## 5. Model (`classification/ml.py`, `merged.py`)

**Stage 1: Q-code rules** (deterministic; `rules.py`).

**Stage 2: ML fallback.** Unchanged baseline features and classifier:

- TF-IDF on word 1–2-grams plus character 3–5-grams;
- logistic regression with `class_weight='balanced'`.

It is used only when the Q-code is missing (AAI) or ambiguous. Category and severity are separate models trained independently: a row with only one valid label still counts for that field.

Two adjustments to the pipeline:

- **Small-data fix.** The character n-gram `min_df` is 1 below 20 training texts. Previously, a small field could crash training with "no terms remain".
- **Low confidence.** A severity probability below 0.55 gives RESTRICTIVE (conservative).

**Keyword guard.** It can only *raise* severity. It now ignores text that says the activity is deactivated, cancelled or not active, consistent with the rules' CD/CN/AK/HQ → ADVISORY. It also reports the exact text span it matched. It no longer overwrites a confident ML category; a disagreement is recorded as uncertainty instead.

**Explainability.** Every classification returns:

- category, severity, confidence and method;
- the rule that fired;
- the keyword guard match;
- reasons for uncertainty;
- class probabilities.

The reason, keyword and uncertainty are stored in `notam_event` (migration `004_classifier_explanation.sql`) and returned by `GET /notams/relevant`.

## 6. Evaluation methodology

### 6.1 Weak-label cross-validation (in-distribution, not independent)

- **What it tests.** The Q-code is hidden, and the model must reproduce the Q-code-derived labels from autorouter-style E-text.
- **Protocol.** StratifiedGroupKFold (3 folds × 5 repeats). Groups are the NOTAM identity, or the text template in the stricter run.
- **Reporting.** Confusion matrices and per-class support come from **repeat 0 only**, i.e. one prediction per NOTAM; variability is reported per repeat. The previous version pooled 5 repeats, giving 650 "predictions" for 130 examples, which overstated the sample size.

| Setting (17 Nov run, 114 de-duplicated examples) | Category macro-F1 (repeat 0) | per-repeat mean ± sd | Severity macro-F1 (repeat 0) | per-repeat mean ± sd | Severity under-classification |
|---|---|---|---|---|---|
| Rules only, Q-code hidden | 0.000 | 0.000 ± 0.000 | 0.073 | 0.073 ± 0.000 | 2.6 % |
| ML argmax | 0.906 | 0.892 ± 0.012 | 0.891 | 0.925 ± 0.024 | 3.5 % |
| Merged (ML + threshold + guard) | 0.906 | 0.892 ± 0.012 | 0.891 | 0.920 ± 0.019 | 3.5 % |
| Merged, folds grouped by text template | 0.906 | 0.901 ± 0.009 | 0.908 | 0.923 ± 0.015 | 2.6 % |

**Interpretation.** These scores are high because the test texts look like the training texts (the same autorouter style and recurring templates), and because the labels come from rules.

- Severity has only 3 BLOCKING examples, all ISRO launch NOTAMs.
- Category has only 3 NAV_WARNING examples.

The perfect BLOCKING score therefore says almost nothing. This section must not be presented as the system's accuracy on AAI NOTAMs.

### 6.2 Human-label evaluation (independent; `classification/experiment.py`)

1. Validate the annotations: one example per NOTAM; invalid or conflicting fields excluded.
2. **Leakage audit.** Count NOTAM identities, text templates and exact texts shared between the weak training set and the sheet. The earlier human-label check trained on *all* weak data, including the AAI-matched examples, and scored *all* annotated rows. Any NOTAM in both sets was therefore in training and test at once. The audit reports how many.
3. **Frozen holdout.** 30 % of annotated NOTAMs, drawn once with StratifiedGroupKFold:
   - grouped by **near-duplicate cluster**: texts whose character 3-5-gram TF-IDF cosine similarity is at least 0.8, or that share the first-six-token template, are joined by union-find (`experiment.similarity_clusters`; 227 clusters among the 300 NOTAMs), so recurring NOTAM series stay on one side;
   - stratified by severity;
   - rare classes moved into the holdout when they have at least two template groups, otherwise reported as not evaluable.

   It is saved to `data/labelled/aai_holdout_split.json` and reused: same split, same numbers. The holdout is never used for training or tuning.
4. **Leakage removal.** Every model scored on a set is trained with that set's identities, templates *and near-duplicate clusters* removed from both its weak and its human training data. `classification.train` applies exactly the same exclusion, so the saved model is the evaluated one (checked: identical hold-out scores).
5a. **Novelty.** For each hold-out NOTAM, the maximum cosine similarity to any training text is reported, and scores are repeated on the novel subset (similarity below 0.6).
5. **Development CV.** Repeated StratifiedGroupKFold on the development part only, with baseline and improved on **identical folds**. Metrics are given per repeat (mean ± sd), plus the paired difference and the number of repeats where the improved model wins. A threshold-sensitivity table (0.40–0.70) is computed on development data only.
6. **Holdout scoring.** Both models are scored once on the holdout, with:
   - accuracy, macro-F1, macro-precision and macro-recall;
   - per-class P/R/F1/support and confusion matrices;
   - the severity under-classification rate;
   - the number of unique NOTAMs.

   A bootstrap over holdout NOTAMs gives a 95 % interval for the macro-F1 difference.
7. **Verdict.** "Improvement supported" only if the improved model wins in every development repeat *and* the bootstrap interval is above zero. Otherwise "NOT established".

| Model | Training data |
|---|---|
| **baseline** | weak labels only (the original model) |
| **improved** | weak + human development labels; identical features and classifier, so any difference is due to in-domain labelled data |

**Why cluster grouping.** A first run grouped only by the six-token template. Hold-out severity macro-F1 then came out at 0.862 against 0.563 in development CV, a gap explained by the same recurring NOTAM series (for example daily danger-area activations with changed times) appearing on both sides. Grouping by similarity cluster removed it; the numbers below are from the cluster-grouped split. The template-only numbers are not reported as results.

### 6.3 Results on the frozen hold-out (101 NOTAMs; severity RESTRICTIVE 59, ADVISORY 36, BLOCKING 6)

Leakage audit, weak set against the sheet: 1 shared NOTAM identity, 11 shared templates, 5 shared exact texts, all removed from training before scoring.

| Model (merged classifier) | Training data | Category acc | Category macro-F1 | Severity acc | Severity macro-F1 | Severity under-classification |
|---|---|---|---|---|---|---|
| Baseline | 103 weak | 0.772 | 0.763 | 0.614 | 0.548 | 0.347 |
| Improved | 186 human + 102 weak | 0.812 | 0.733 | 0.812 | 0.739 | 0.050 |

Severity F1 per class (baseline, improved): BLOCKING 0.40, 0.57 (improved recall 4 of 6); RESTRICTIVE 0.60, 0.85; ADVISORY 0.65, 0.80. ML component alone, severity macro-F1: 0.286, 0.680.

Development CV (5 repeats, identical folds): category 0.510 ± 0.030 vs 0.567 ± 0.012; severity 0.364 ± 0.002 vs 0.587 ± 0.010. The improved model is better in 5 of 5 repeats for both fields.

Bootstrap of the hold-out difference (improved minus baseline): severity +0.189, 95 % CI [0.050, 0.350]; category −0.028, 95 % CI [−0.168, 0.100].

Novelty: hold-out similarity to training ranges 0.13 to 0.78 (median 0.46); none at or above 0.8; 61 NOTAMs below 0.6. On those 61, severity macro-F1 is 0.564 (baseline) vs 0.667 (improved), category 0.753 vs 0.628.

**Verdict (rule in step 7).**

- **Severity: improvement supported.** Better in every development repeat, bootstrap interval above zero, and it holds on novel texts. Under-classification (predicting a less severe class than the annotator) falls from 35 % to 5 %.
- **Category: improvement NOT established.** Development CV favours the improved model, but the hold-out macro-F1 is slightly lower, the interval spans zero, and on novel texts it is clearly worse. The category labels in AAI wording are less consistent (see the audit), and the small classes (NAVAID_COMMS 4, PROCEDURE 9 in the hold-out) make the estimate unstable.

The keyword guard was checked on development folds only: it changes category macro-F1 by +0.003, so it is not the cause of the category result.

Full tables, confusion matrices and threshold sensitivity are in `evaluation/results/classifier_eval.md`.

## 7. Investigating the reported severity problem

The brief reported that the model predicts ADVISORY where annotators said BLOCKING or RESTRICTIVE. With the final sheet this is confirmed and measured: the weak-label baseline under-classifies 34.7 % of hold-out NOTAMs. The causes visible in the data:

- **Class imbalance in the weak labels.** ADVISORY 97, RESTRICTIVE 14, BLOCKING 3 (85 % ADVISORY), while the annotators labelled 59 % of AAI NOTAMs RESTRICTIVE.
- **Too few BLOCKING examples.** The 3 weak BLOCKING examples are near-identical rocket-launch texts.
- **Domain shift.** Weak labels come from autorouter-style text; AAI E-texts use different wording and PDF extraction artefacts.

The fix is the in-domain human training data (section 6.3), not new rules: under-classification falls to 5.0 %. No keyword rules or synthetic labels were added to raise recall. The 0.55 low-confidence threshold was left unchanged; the development-only sensitivity table shows that 0.40 would give a higher ML severity macro-F1 (0.747 vs 0.590), but it was not tuned on, or applied to, the hold-out. Changing it is a decision for the team and would need a fresh hold-out.

## 8. Commands

```powershell
python -m classification.annotations                 # audit the sheet
python -m classification.train --labels weak         # baseline model only
python -m classification.train                       # weak + human (hold-out excluded)
python -m classification.evaluate                    # all evaluations (+ audit)
python -m classification.evaluate --resplit          # redraw the frozen hold-out (changes results)
python -m classification.train --use-holdout         # final deployment model; hold-out numbers no longer apply
```

## 9. Limitations

- **One annotator, preliminary labels.** No agreement was measured. Suggestion: double-annotate 50 rows and report Cohen's κ before relying on the per-class numbers.
- **Questionable labels found by the audit** (`evaluation/results/annotation_audit.md`; nothing was changed): 13 airspace activities (firing, danger areas) labelled AERODROME; 10 activated designated areas and 6 firing or no-flight notices labelled ADVISORY; 3 aerodrome closures labelled RESTRICTIVE; 3 Airspace Use Plan notices labelled BLOCKING; 2 NAV_WARNING BLOCKING labels without closure or prohibition wording; 1 NAVAID_COMMS BLOCKING. 161 rows carry only a generic note. These affect both training and scoring and should be reviewed by the annotator.
- **Small classes.** The hold-out holds 6 BLOCKING, 4 NAVAID_COMMS and 9 PROCEDURE NOTAMs, so per-class scores have wide intervals. AIRSPACE and OTHER cannot be evaluated.
- **Near-duplicate threshold.** The 0.8 cosine threshold is a judgement; the novelty table shows how scores change on texts unlike the training data.
- **No geometry or flight-level information for most AAI NOTAMs.** Severity cannot use where or how high a NOTAM applies; that is handled at the routing stage.
- **Deployment model.** `classification.train` (default) excludes the hold-out, so the reported numbers apply to it. `--use-holdout` trains on all 300 labels for deployment; hold-out numbers then no longer apply.
